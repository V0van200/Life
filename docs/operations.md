# Запуск и сохранность данных

## Что размещать

Pages — клиентский сайт. Backend — отдельный Python/Docker-хост. PostgreSQL — постоянный volume либо управляемая база. Копирование нового кода не должно создавать новую пустую базу.

Прежде чем открыть API в интернет: настроить HTTPS, точный CORS origin, login rate limit на reverse proxy, лимит тела запроса (например 1 MiB), закрыть прямой доступ к БД, обеспечить журналирование ошибок без паролей и токенов. API пока не имеет встроенного распределённого ограничения попыток входа и общего лимита размеров JSON, поэтому в compose порт ограничен loopback. Не менять привязку на 0.0.0.0 для обхода этих шагов.

## Резервная копия PostgreSQL

```bash
mkdir -p backups
docker compose exec -T db pg_dump -U life -d life -Fc > backups/life.dump
```

Копию зашифровать и сохранить вне сервера. Она содержит личные записи и хеши авторизации. Настроить расписание и срок хранения на хостинге; в этом репозитории расписание не установлено.

Проверять восстановление в отдельной базе:

```bash
docker compose exec -T db createdb -U life life_restore_test
docker compose exec -T db pg_restore -U life -d life_restore_test --no-owner < backups/life.dump
```

Открыть восстановленную БД отдельным тестовым API, проверить записи, суммы и связи. Не направлять тесты pytest в рабочую БД.

## Обновление

Сначала backup и проверка миграций на копии, затем новая версия образа и `alembic upgrade head`. В compose migrate выполняется перед запуском API. Разрушительный downgrade не заменяет откат: для критических изменений нужен план восстановления базы. Контейнер API не запускает create_all и не пересоздаёт таблицы на старте.

## Доступ

Создание пользователя: `docker compose exec api python -m life.cli create-user vovan`.
Смена пароля и отзыв всех сессий: `docker compose exec api python -m life.cli reset-password vovan`.
Сессии истекают через 12 часов. Периодическую очистку истёкших строк необходимо добавить при настройке обслуживания.

## Статус проверки

Локальные API-тесты используют SQLite и проверяют авторизацию, изоляцию владельцев, деньги, идемпотентность, повторные платежи, календарь, версии, учебный прогресс, пользовательские типы и CSV. PostgreSQL включён в GitHub Actions; результат удалённого прогона нужно смотреть отдельно. Docker/публичный хостинг и реальное восстановление PostgreSQL не считаются проверенными только на основании локальных SQLite-тестов.
